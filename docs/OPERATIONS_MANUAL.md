# 운영 매뉴얼

## 운영진 계정 관리

운영진 계정은 공개 가입으로 만들지 않습니다. 승인된 운영진이 `/admin/members`에서 직접 생성·재설정·회수합니다. 계정 관리 과정에서 이메일을 발송하지 않습니다.

### 1. 계정 만들기

1. `/admin/login`에서 승인된 운영진 계정으로 로그인합니다.
2. 상단 **운영진** 메뉴(`/admin/members`)를 엽니다.
3. 새 운영진의 이메일과 8자 이상의 임시 비밀번호를 입력하고 **운영진 계정 생성**을 누릅니다.
4. 임시 비밀번호는 당사자에게 개별 전달합니다. 첫 로그인 뒤 상단 **설정**에서 새 비밀번호로 바꾸도록 안내합니다.
5. 생성 즉시 해당 계정은 콘텐츠·사진·운영 설정을 수정할 수 있는 승인된 운영진 권한을 받습니다.

### 2. 비밀번호 재설정

1. `/admin/members`의 해당 운영진 옆 **비밀번호 재설정**을 누릅니다.
2. 새 임시 비밀번호를 입력해 변경합니다.
3. 새 비밀번호를 당사자에게 개별 전달합니다. 이메일 발송은 필요하지 않습니다.

### 3. 계정 회수

1. `/admin/members`에서 퇴임 운영진의 **계정 삭제**를 누릅니다.
2. 확인을 위해 대상 이메일을 다시 입력하고 삭제합니다.
3. 본인 계정은 삭제할 수 없으며, 마지막 남은 운영진 계정도 삭제 버튼이 비활성화됩니다. 이 제한은 운영진 전체가 접근 권한을 잃는 사고를 막기 위한 것입니다.

### 4. /admin에서 비밀번호 변경

1. `/admin/login`에서 로그인합니다.
2. 상단 **설정** 메뉴를 엽니다.
3. 새 비밀번호를 두 번 입력하고 **비밀번호 변경**을 누릅니다.

이 기능은 로그인한 본인 계정에만 적용되며, 이메일 발송을 사용하지 않습니다.

## 비상 절차: 모든 운영진이 로그인할 수 없을 때만

평상시에는 Supabase 대시보드에서 계정을 만들거나 수정하지 않습니다. 모든 운영진 계정에 접근할 수 없는 비상 상황에서만 다음 절차를 사용합니다.

1. Supabase 프로젝트 대시보드에서 **Authentication → Users**를 엽니다.
2. **Add user → Create new user**를 누르고 복구 담당자의 이메일과 임시 비밀번호를 입력합니다.
3. **Auto Confirm User**를 체크한 뒤 계정을 만듭니다.
4. **Table Editor → admin_members**에서 해당 사용자의 행을 찾습니다. 없으면 `user_id`, `unid`, `display_name`을 입력해 행을 만듭니다.
5. 해당 행의 `role`을 `admin`으로, `approved_at`을 현재 시각으로 설정합니다.
6. 복구 담당자가 `/admin/login`에 로그인한 뒤 `/admin/members`에서 나머지 운영진 계정을 다시 관리합니다.

## 서버 키 관리

`SUPABASE_SERVICE_ROLE_KEY`는 `/admin/members`의 서버 API에서만 사용합니다. Vercel 프로젝트의 **Environment Variables**에 Production과 Preview 환경으로 등록하며, `NEXT_PUBLIC_` 접두사를 붙이거나 코드·Git에 저장하지 않습니다.

유출이 의심되면 다음 순서로 처리합니다.

1. Supabase 대시보드에서 service role 키를 rotate합니다.
2. Vercel의 `SUPABASE_SERVICE_ROLE_KEY` 값을 새 키로 교체합니다.
3. Vercel에서 Redeploy합니다.
4. `/admin/members` 목록을 열어 정상 동작을 확인합니다.
